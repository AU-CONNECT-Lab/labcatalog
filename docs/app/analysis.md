# Analysis

The Analysis page runs the analyses most papers need on the datasets you choose: a look at missing data, a correlation table, regressions, a group comparison, rater agreement, a measurement model, measurement invariance across groups, mediation, a multilevel model and a cross-lagged panel model, each on its own tab beside the Sample, and a Custom tab for any other analysis, scripted with a language model's help. Each result is a table ready for a manuscript, with a chart, a **Copy table** button, **Save to outputs**, and a **Code** section with the R and Python code that reproduces it. Where the result has a chart, the code ends by drawing it again, with ggplot2 in R and matplotlib in Python, and saving it as a PNG beside the data; the correlation chart follows the Heatmap or Dots choice. A note under each result says whether it was computed in R or in Python. The correlation table, the regressions and the group comparison also write a **Results paragraph** in APA style, with a **Copy text** button: the significant correlations (each pair when there are three or fewer, otherwise the five strongest), each predictor's *b*, *SE*, *p* and *R*², or the groups' means with the test and its effect size. Significance is *p* < .05, and the numbers have the decimal places set on the Settings page. With a language model set up (see [Set Up R and Language Models](../how-to/r-and-models.md)), **Interpret with the language model** under any Results paragraph, here or on an instrument's page, asks the model for a short interpretation of the result and a list of things to check. It sends the tables and the paragraph, never any data, and its answer is a draft to check against the tables.

## Sample

The Sample on the left applies to every tab except the multilevel model.

- **Datasets**: the data files to analyze. By default, every dataset of the first wave of the first study.
- **Only people in every selected dataset**: on (the default) keeps the people who are in all of them; off keeps everyone in any of them. With datasets of several studies, it is every selected dataset of the person's own study.
- **Measures**: the instruments whose scores and numbers appear in the lists below, the multilevel model included. By default, all of them. The **Select** menu next to it can choose all, all of one modality, or none.

The note below says how many people are in the sample and how they were matched across files: by ID, or by group when `stats.correlate_by` names one. IDs belong to their study, so files of two studies share no one: with files of several studies, each person's ID is written with their study first, as `pilot/1001C`. Rows whose ID repeats within a file are left out. When a file holds several people of one group (two children of a family), that group is taken person by person, as described under [Groups](../concepts/ids-groups-missing.md#groups), and the note says how many groups that affects.

(several-studies)=
### Several studies

Choosing datasets of more than one study pools the studies. Each study's people are matched within that study, as above, and the studies' people are then put together, one row each. A variable is offered when every chosen study has it in exactly one chosen dataset of a reporter, for example the mood total in wave 1 of one study and in the baseline of another; each person's value comes from their own study's file. A score that two reporters give, such as a child's and a parent's ratings of the child, is offered once for each, with the reporter after its name. Choose one wave of each study for the variables to pool. The group comparison also offers **Study** as the groups.

The analyses allow for the study, so that a difference between the studies' means does not show up as a correlation:

- The correlation table gives each pair's correlation within studies: the correlation of what is left of the two variables once each study's mean is taken out, with the *p* value of the variable's coefficient in a linear model with the study. For Spearman's ρ, the same on the ranks of each pair. Below it, **Correlations in Each Study** gives each pair's correlation in each study on its own, with its *n*, beside the correlation within studies.
- Each regression includes the study as a fixed effect, a dummy for each study but the first. The slope is the slope within studies, the intercept is the first study's, and *r* is the correlation within studies, so the table gives no interval for it.
- Missing data and the group comparison work as for one study.
- The measurement model regresses every factor on the study, a 0/1 covariate for each study but the first, so the factor correlations are within studies, and the standardized loadings are those of the pooled sample. Each study's people bring their own file's items. This takes the items to work alike in every study, which Invariance tests. ω comes from the same factors fitted without the study, since semTools' ω does not take covariates.
- Invariance offers each instrument that every chosen study has in one chosen dataset, and **Study** as the groups: a multigroup model with one group per study, which tests whether the instrument measures the same thing in each study before their scores are put together.
- Mediation includes the study as a fixed effect on M and Y, a 0/1 covariate for each study but the first, named as Study: and the study's label. In Items mode the factors take each study's people's items from their own file, and the study predicts the factors of M and Y.
- Rater agreement gives κ on everyone of the studies together, and intraclass correlations within studies: each rating less its study's mean rating, so that a difference between the studies does not count as agreement. A second table gives each study on its own: each pair's κ, or ICC(2,1) and ICC(2,k), and the Results paragraph adds them.
- Multiple imputation imputes each study by itself, with the same choices, and each person's values come from their own study's imputation. The correlation table and regression then pool the correlations and slopes within studies over the imputed data sets (see [Multiple imputation](#multiple-imputation)).

The multilevel model and the cross-lagged panel pick their own waves, and each takes several studies in its own way (see [Multilevel model](#multilevel-model) and [Cross-lagged panel](#cross-lagged-panel)).

The variable lists hold every score and number item of the chosen measures in the chosen datasets, labeled with their wave. Type in a list to filter it.

## Missing data

Choose the **Variables**; by default, every score of the chosen measures. The first table gives each variable's *n*, the number of people without a value, and their percentage, among the people in the Sample. The second lists each pattern of which variables people have (1) and lack (0), with how many people have it, the most common first, as `mice::md.pattern` shows them. The Results paragraph gives how many people have every variable and the range of missing values.

The correlation table, regression and group comparison each use everyone with values on what they need, and their table notes give the *n*, unless they are set to multiple imputation.

(multiple-imputation)=
### Multiple imputation

The data of the Sample are imputed once, and every section set to multiple imputation works on that one imputation. **Imputed** lists what the imputation holds, by default the questionnaires of the chosen datasets: every score made of answer-option items, imputed item by item (with reverse-keyed items reversed) and computed again from its items in each imputed data set, and the demographics' answer-option items, imputed as categories so that a group comparison can use them. Scores and numbers of other modalities join when chosen. **Other scores that help impute** adds scores imputed as they are, to carry information into the model (auxiliary variables). **Imputed data sets** and **Seed** start from the project's settings. The imputation runs in R with `mice`, by predictive mean matching, each column predicted by the columns that correlate at least .10 with it or with its missingness (`quickpred`).

**Run** imputes, or reads the imputation already made from the same data and choices, and shows each imputed column's missing count with its observed and imputed *M* (*SD*), and anything `mice` reported doing, such as leaving out a column that another predicts exactly. **Save to outputs** under it writes the data, the R script, and `imputed.csv`: every imputed data set stacked under the observed data, numbered in the `.imp` column (0 for the data as observed), with each score computed again, for analyses of your own.

When the project's **Missing values** is set to multiple imputation, the correlation table, regression and group comparison use the imputation; the **Missing values** switch on each of them tries the other choice for that section. A variable a section needs that the imputation leaves out is named, to add here. The imputation is kept in a file named after the data and the choices, so it is made once and read again by every section, and made again when the Sample, the data or the choices change. A section's saved R script imputes the same way and keeps the file beside itself.

With multiple imputation, the correlation table gives each variable's *M* and *SD* averaged over the imputed data sets and each correlation pooled with `miceadds::micombine.cor` (Fisher's *z* and Rubin's rules), for everyone in the Sample. Each regression is fitted in every imputed data set and pooled with `mice::pool`, with *r* and its CI from `micombine.cor` and *R*² from `mice::pool.r.squared`; its chart still shows the observed values. The group comparison keeps everyone whose group is known, with the outcome imputed: two groups are compared with Student's *t* from the group coefficient of a linear model, pooled with Rubin's rules, and Cohen's *d* averaged over the imputed data sets; three or more with the pooled Wald test of the groups (`mice::D1`) and η² and ω² averaged over them. With datasets of several studies, each study is imputed by itself; the correlations are then taken within studies in each imputed data set (on the ranks in each data set for Spearman's ρ) and pooled with `micombine.cor`, with the *p* value of the variable's coefficient in a linear model with the study, pooled with `mice::pool`, and **Correlations in Each Study** pools each study's own correlations; each regression includes the study as a fixed effect in every imputed data set. The multilevel model, mediation, measurement model and invariance tests do not use the imputation; the factor models use full-information maximum likelihood where their tables say so.

## Correlation table

Choose the **Variables**; by default, every score of the chosen measures, without the number items. The **Select** menu adds all variables, all of one wave or all of one modality.

The table lists each variable's *n*, *M* and *SD* and the correlation of every pair, with stars for *p* < .05, .01 and .001. Each pair uses everyone with both values. The coefficient is the project's (Pearson's *r*, or Spearman's ρ when `stats.correlation` is `spearman`); the switch beside the variables tries the other for this table. With three or more variables, a chart above the table shows the correlations as a **Heatmap** or as **Dots**.

Below the Results paragraph, **Measures paragraphs** give one paragraph for each instrument of the chosen variables in each dataset, as the instrument's page writes it, with Cronbach's α from that dataset; **Copy text** copies them all. McDonald's ω is on the instrument's page and the Methods page, which run the factor models. The Regression tab gives the same paragraphs for its outcome and predictors.

## Regression

Choose one or more predictors (**X**) and an outcome (**Y**). Each predictor gets its own simple regression on everyone with both values. The table gives *n*, *r* with its 95% CI, *p*, the slope and intercept with their standard errors, and *R*². The chart plots the outcome against each predictor with its fit line, the distributions on the margins and the residuals in an inset. Hover over a point to see the person's ID.

## Group comparison

Choose the **Groups**, an answer-option item of a demographics instrument (the roster's items are offered for every chosen file), and the **Outcome**. Groups with fewer than two people are left out. With two groups, the test is the project's (Welch's *t* test, or Student's when `stats.t_test` is `student`; the switch beside the outcome tries the other), with Cohen's *d* and the mean difference, each with a 95% CI. With three or more, it is a one-way ANOVA with η² and ω². The page shows a table of *n*, *M* and *SD* per group, the test table, and a box plot with every person as a point.

## Rater agreement

Choose one variable for each rater: the same people rated by two or more coders, each coder's ratings in a column of their own. When every chosen variable is an item with answer options, the table gives Cohen's κ for each pair of raters on everyone both rated, unweighted and with quadratic weights (for ordered options), each with its 95% CI (`psych::cohen.kappa`), and with three or more raters their average (Light's κ). Otherwise it gives the six intraclass correlations of Shrout and Fleiss with their 95% CIs, *F* tests and *p* values (`psych::ICC` with its variance components from `lme4`, as JASP gives them), on everyone with at least one rating; these need R. The Results paragraph reports ICC(2,1) and ICC(2,k), or the κ.

## Measurement model

Choose two or more **Factors**, scores of two or more items each, from any of the chosen datasets; by default, the totals of the first dataset that has two. Each score becomes a factor of its own items and the factors correlate freely, the measurement model a paper reports before a structural model. Scores must not share items, so a total and its subscales cannot be chosen together. **Fit** runs the model in R with lavaan on the people of the Sample who answered every item, with **WLSMV** (the items as ordered categories, offered when every item has answer options), **ML** or **MLR**; the default is `stats.cfa_estimator`. A path diagram shows the model as chosen, each factor above its items with the factor correlations as arcs, and after the fit carries the standardized loadings and correlations. The page then shows the fit (χ², CFI, TLI, RMSEA with its 90% CI, SRMR), the standardized loadings with each factor's ω, and the factor correlations with their 95% CIs, with a **Results paragraph**. **Code** holds the R script, and **Save to outputs** writes it with its data (`measurement_data.csv`) and the model as an Mplus input. The factor models on the instrument pages fit one instrument in one dataset at a time; this one fits several together, across datasets and reporters, as the Sample pairs them.

## Measurement invariance across groups

Choose an **Instrument** in one of the chosen datasets and the **Groups**, an answer-option item of a demographics instrument, then press **Test**. labcatalog fits a multigroup factor model in R with one group per answer and tests configural, threshold (for ordered items), metric and scalar invariance, the same steps as across waves on the instrument page. The grouping item may be in another dataset, such as the child's gender reported by the parent; people are matched as in the Sample. With datasets of several studies, **Study** is the first choice of groups (see [Several studies](#several-studies)). A group needs more people than the model has items, and smaller groups are left out and named. **Which items differ** and **Save and rerun** work as on the instrument page, with the freed items stored for this grouping item. **Code** holds an R script that fits the same steps with lavaan and semTools; **Save to outputs** writes it with its data (`invariance_data.csv`) and the Mplus inputs.

## Mediation

Choose X, the mediator M and the outcome Y from the scores and numbers of the Sample, and any covariates, which predict both M and Y. A **Moderator W** is optional; tick the paths it moderates: a (X to M), b (M to Y) or c′ (X to Y, the direct effect). Once W is chosen, a second moderator can be added below it; the two are then W1 and W2, each with the paths it moderates, and their interactions add, with no three-way term (as in Hayes's PROCESS models 9 and 21). The diagram shows the model as chosen. **Fit** runs it in R with lavaan. **FIML** (the default, as in Mplus) keeps everyone with any of the model's values and estimates by full-information maximum likelihood, with the predictors in the model so that people who lack one stay in; **Complete cases** keeps only those with all of them. WLSMV, and modsem's QML for an observed moderator of factors, have no FIML and keep the complete cases, as a note under the diagram says; with a moderator, X, M and W are centred at their means and the conditional effects are taken at W's two answers or at its mean and 1 SD either side; with two, at every combination of the values of the moderators an effect varies with (nine rows for two moderators of a or b). The table gives each path, the indirect effect (a × b) and, without a moderator, the total effect; with a moderator, the conditional indirect and direct effects and, when only a or only b is moderated, the index of moderated mediation. With two moderators, each that moderates only a, or only b while nothing moderates the other, has an index of partial moderated mediation; one on a and the other on b leave no single index. With **Bootstrap**, confidence intervals are percentile bootstrap intervals; set the number of **Bootstrap resamples** (1000 by default). With **None**, they are Wald intervals (by the delta method for the indirect and other defined effects), which take seconds. **ML** or **MLR** sets the estimator: bootstrapping needs plain maximum likelihood, whose estimates are the same as MLR's, so with Bootstrap MLR changes only the fit test; with None, MLR also gives robust standard errors. **Scores** or **Items** sets what the variables are. With Scores, X, M, Y and W are the scores themselves. With Items, X, M and Y must be scores with two or more items, and each becomes a factor of its items (the first item's loading fixed at 1); a moderator that is a score becomes a factor too, and one that is a number or an answer stays observed. Their items must not overlap, so a total and one of its subscales cannot both be factors. Without a moderator the item model runs in lavaan and offers WLSMV, which treats the items as ordered categories (its bootstrap refits by DWLS, whose estimates are WLSMV's). With a moderator it runs in modsem, which fits the latent interaction by LMS, or by QML when the moderator is observed, with the items as continuous; there is then no chi-square test of fit, and each bootstrap resample refits the whole model, so 1000 resamples take several minutes. The table's β column is fully standardized; effects taken at values of W have none. The **Results paragraph** reports the numbers, and **Code** holds the R script, which Save to outputs writes with the data. Save to outputs also writes the model as an Mplus input (`mplus_mediation.inp`) with its data, centred as in R, and with the path to Mplus set on the Settings page, **Run in Mplus** runs it. Mplus bootstraps with ML only, so with MLR its input uses ML, whose estimates are the same; it cannot bootstrap a latent interaction (XWITH with numerical integration), so there its intervals are by the delta method. Mediation needs R, and the Items mode with a moderator needs the R package modsem; the number of R processes for the resamples is on the Settings page.

(multilevel-model)=
## Multilevel model

A linear mixed model of one outcome across waves. This section picks its own waves and keeps everyone with at least one; the Sample does not apply, except for **Measures**.

- **Outcome**: a score or number item. By default, the first total score measured in two or more waves.
- **Waves**: the datasets that hold the outcome, one per wave of each study. By default, those of the first one's study and reporter.
- **Covariates**: a variable from one dataset, used at every wave, or a variable marked "(each wave)", which uses each wave's own value.

Waves of several studies pool them. IDs belong to their study, so each study's people and groups are their own; time counts from each study's first chosen wave (or its earliest visit date), and the study enters as a fixed effect, compared with the first study. Each study needs what one study needs, such as two or more waves for people as a level. A covariate from one dataset then pairs one dataset of each study, named in the list, such as `parent_w1 + s2_parent_baseline`: each study's first dataset that has it, then each study's second, and so on. Each person's value comes from their own study's dataset. On the chart, waves at the same place in each study share a name, such as `1/baseline`.
- **Time counts**: **Waves since the first** (the default) counts the waves since the first chosen wave; a wave you leave out still counts, so waves 1 and 3 give times 0 and 2. **Months, from the dates** and **Years, from the dates** count the time from the earliest visit date in the first chosen wave to each visit, from each dataset's `date_column`, so people seen early or late in a wave get their own times. Every chosen dataset needs a `date_column`; rows without a readable date are left out.
- **Waves within people**: people as a level, with time as set above. On by default.
- **People within each** group: groups as a level, when `labcatalog.yaml` names a group under `ids`. Off by default.
- **Random slope of time for each person**: on by default.
- **Split each-wave covariates into person mean and deviation**: separates the effect between people from the effect within a person. Shown when an each-wave covariate is chosen.

The results are three tables: **Fixed Effects** (*b*, *SE*, *df*, *t*, *p* and 95% CI; with Satterthwaite's *df* in R), **Random Effects** (variances, SDs and the slope-intercept correlation) and **Model Summary** (the ICC of each level, the numbers of observations, people and groups, and fit statistics). A warning appears when the fit is singular, that is, when a random effect cannot be estimated from these data; a simpler model, such as one without the random slope, may then fit.

Under them, a **Results paragraph** with a **Copy text** button gives the model's design and sample, the ICC, each fixed effect and the SD of each random effect. Below that, a chart of the trajectories draws each person's values across the waves as thin lines, each wave's mean as a circle, and the fixed effects' prediction (intercept plus time) as a thick line. With time from the dates, the axis counts months or years. With covariates in the model, the line is the prediction for the mean of each number covariate and the reference option of each answer covariate.

**Save to outputs** writes the tables, the chart, the R and Python code, and `multilevel_data.csv`, with one row per person and wave.

(cross-lagged-panel)=
## Cross-lagged panel

Choose **X** and **Y**, two scores or numbers each measured at three or more waves of one study; the waves both have are used, one dataset per wave from the first one's reporter, and people in different datasets are matched as everywhere on the page. Like the multilevel model, this tab keeps everyone with a value and the Sample does not apply. **Fit** fits three models in R with lavaan, by robust maximum likelihood (MLR) with full-information maximum likelihood for missing values: the random intercept cross-lagged panel model (RI-CLPM) of Hamaker, Kuiper and Grasman (2015), as Mulder and Hamaker (2021) write it, with each lagged path free; the same with each kind of lagged path held equal across waves; and the cross-lagged panel model without random intercepts (CLPM).

The diagram shows X above Y, a column per wave, with the random intercepts loading on each row and the standardized lagged paths. The tables give the three models' fit with the scaled chi-square difference tests between them (equal paths against free, and the CLPM against the RI-CLPM, a test at the boundary whose *p* is conservative), the standardized lagged effects of each model at each transition, and the correlation of the random intercepts (between people) and of X and Y at each wave (within people). The Results paragraph reports the paths from the equal model when holding them equal does not worsen fit, and from the free model otherwise. **Save to outputs** writes the data, the R script, and the three models as Mplus inputs with their data.

When two or more studies measure both X and Y at three or more of the same waves, **Studies** chooses which to fit; by default, the first. With several chosen, each must share as many waves, and their first waves are put side by side, then their second, named like `1/baseline`. IDs belong to their study, so each study's people are their own. Each study is a group of one multigroup model (lavaan's `group`), with its own means, variances and paths, and two more models hold the lagged paths equal across the studies: free across waves, and equal across waves. Their scaled chi-square difference tests say whether the paths differ between the studies. The paths are reported from the model chosen across waves as above, held equal across the studies when that does not worsen fit. The tables give each study's paths and correlations, the diagram the first study's, and the Mplus inputs group by study, with each study's own intercepts.

## Custom

For an analysis the other tabs do not offer. Choose the **Variables**, say in **The analysis** what you want, pick **R**, **Python** or **Mplus** and click **Draft**: the language model set on the [Settings](settings.md) page writes a script, which appears in the editor with anything it could not settle listed under **To check**. Draft sends what you wrote with the chosen columns' names, labels, answer options and how many people have a value, never the data; paste a few rows into the box yourself if the model needs to see them. Without a language model, write the script in the editor yourself.

The script reads `analysis_data.csv` from its own folder: one row per person of the Sample, the chosen variables, and each chosen score's items, reversed where the scale says so. **Run** runs it on this computer, R scripts with the Rscript set on the Settings page and in turn with the page's other R analyses, Python scripts with labcatalog's own Python; **Stop** ends it. What it prints appears under **Output**, with the figures it saves as `.png` and the tables it saves as `.csv`. When it stops with an error and a language model is set, **Ask the model to fix it** sends the script and its output and shows the changes it proposes; **Use it** puts them in the editor. **Save to outputs** writes the data, the script, its output and every file it wrote. The script reads the data as they are, without multiple imputation.

**Mplus** is for models with latent variables or structural equations: factor models, structural equation and path models, multigroup and multilevel structural equation models, growth models, latent class and mixture models. For anything else the model writes nothing and suggests R or Python. labcatalog writes the start of the input itself: the title, a comment line giving each column's short Mplus name (at most eight characters), `DATA: FILE = analysis_data.dat;`, the names and the missing value code. The data file has no header, numbers each ID, and writes missing values as -999. The model writes the rest of the input. **Run** needs the path to Mplus on the Settings page, and shows the `.out` file.

**Keep in project** saves the script in the project's `analyses` folder, under a name of lower-case letters, digits and `_`, and lists it under `analyses` in `labcatalog.yaml` with the datasets, the Sample's switch, the variables and what you asked for. Kept analyses appear at the top of the tab under **Saved**: a click opens one, setting the Sample and the variables as they were, ready to run again on the data as they are now; the cross beside it removes it and its script. Keeping one under a name already kept replaces it.

## Saved files

Every **Save to outputs** on this page writes a new folder in `outputs/` with the tables as `.csv`, `.docx` and `.tex`, the chart as `.png` and `.svg`, the data and the R and Python scripts, and `manifest.json`. See [Copy Tables into a Manuscript](../how-to/copy-tables.md).
